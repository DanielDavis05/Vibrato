# Round 0 campaign supervisor

Runs isolated offline singleplayer clients. Raw logs, saves, metadata and summaries stay in `~/.vibrato-tests/round0/`; no original save is loaded. `seeds.json` is fixed, but its terrain types have not been surveyed. A run passes only when the live heartbeat reports Nether entry. A probe that runs out of time has not passed the campaign goal.

Build and commit this checkout first, with `./gradlew test build -PbaritoneDist=/opt/Baritone/dist`. Install a separate Minecraft/Fabric profile and the built mod using `VIBRATO_FLEET_HOME=$HOME/.vibrato-tests/install python scripts/fleet/launch.py install` in an environment containing `minecraft-launcher-lib`. Start a dedicated Xvfb separately, then invoke e.g. `python scripts/campaign/supervisor.py --install "$HOME/.vibrato-tests/install" --campaign round0 --label single --count 1 --budget 60 --display :100`. Use fresh labels and run four and six only after the preceding probe completes. Labels accept short directory-safe names such as `six-steady-2`. Use `--stagger 0` and a long enough budget when measuring simultaneous active worlds; staggered startup alone does not establish steady concurrency. `--seed-offset 6 --count 4` selects the last four entries of the ten-seed list; the list wraps for larger offsets. A different install must not be changed during a run.

Each run holds `metadata.json`, `client.log`, `script-result.json` if emitted, `campaign-heartbeat.json`, `summary.json`, its own game directory, and a symlink to the campaign's installed immutable mods. Summaries use schema version 1, record the git SHA, jar SHA-256 and unchanged check, both seeds, stage, outcome, watchdog cause, last 50 task starts, task-start count, heartbeat, CPU seconds and average percentage of one core, peak RSS, and mean sampled client tick cadence. The supervisor's labels distinguish failures from invalid outcomes. Ten-sample averages below 18 ticks per second in either client or integrated-server cadence mark a timing-invalid overload. Both need ten samples; missing server telemetry is invalid rather than a pass. Less than ten samples cannot establish a valid capacity measurement. Peak RSS and CPU are sampled from the client process only; they omit Xvfb. A stop on Nether entry or watchdog may terminate the client before its final script result is written.

Task-start churn requires a matching sampled leaf identity and class within the same ten-second window. Debug state after the closing bracket is ignored; unrecognized or ambiguous identities fail open. This can still miss fast transitions. Restart counts are repeated observed task descriptions, including parent restarts, rather than unique task object lifecycles. Stalls require 60 seconds without a task start or 0.25 blocks of movement. Neither is an authoritative in-game progress measure. Unknown or unavailable values stay null. Signal handling targets only subprocess groups created by this supervisor. Shutdown via SIGKILL cannot execute cleanup; inspect owned process IDs in metadata if the supervisor itself is forcibly killed.

Only share manually reviewed redacted excerpts: `python scripts/campaign/redact.py < raw.log > excerpt.txt`, then scan for `/home`, `@`, `token`, `password`, `uuid` and other identifying strings. Redaction is not a proof of anonymity. Run harness tests with `python -m unittest discover -s scripts/campaign`.
